# 产品定位方案：统一科研对话入口

> 版本：v1.0（2026-08-15）
> 状态：已确认产品方向，代码按此实施。

## 一、产品一句话定位

**"面向科研小白的 AI 科研伙伴：有需求就说话，系统自动选对工具、走对流程。"**

核心心智模型：用户不需要知道背后有顶层 Agent、工作流、skill 等概念，只需要「说话」。系统替用户决定：随手答、检索、还是走一个多步流程。

## 二、三层产品结构（用户视角）

```
第一层：统一对话入口（顶层 Agent）
  用户说一句话 → 系统判断该怎么做
第二层：执行路径（后端自动选择）
  ├─ 随手答：翻译 / 检索 / 分析 / 问答
  ├─ 科研 skill：文献综述 / 论文写作 / 评审
  ├─ 专用 Agent：写作 / 实验 / 数据 / RAG
  └─ 工作流模板：多步任务 / 需人工确认 / 可复用
第三层：能力底座（共用同一数据库）
  文献库(6维向量) / 写作项目 / 实验 / 数据
```

## 三、功能定位

| 功能 | 用户理解 | 使用场景举例 | 一句话记忆 |
| --- | --- | --- | --- |
| 对话（顶层 Agent） | 统一入口，随口说就有结果 | 检索文献、翻译、分析数据 | 灵光一闪，随口就问 |
| 科研 Skill | 专业的单步能力 | 文献综述、论文写作、同行评审 | 专业的事，一键做 |
| 工作流模板 | 规范的多步流程，关键处停下确认 | 写综述（检索→对比→起草→确认） | 正规流程，按步骤走 |
| 白板/自然语言生成 | 用户自己定义流程 | 我要先A再B，中间判断一下 | 我搭流程，存成模板 |

**边界规则（系统自动判断，用户无需理解）：**
- 一步能办成 → 对话直接给结果
- 需要多步 / 要确认 → 对话自动转工作流（"这需要走流程，我用模板××"）
- 想记住流程 → 对话里生成并保存为模板

## 四、体验优化设计

1. 对话回复带「路径标签」：每条回复末尾加小徽标，如 `已走：文献检索`、`已走：综述模板`。
2. 模板卡片写「适用场景」：每个工作流模板一句话讲清何时使用，而非只列技术步骤。
3. 对话即唯一入口：工作流、skill 都收进对话背后，从根上消除"该点哪个功能"的困惑。

## 五、顶层 Agent 与工作流的关系（产品口径）

**顶层 Agent 是脸（入口路由），工作流是手（多步执行器）。**
- 顶层 Agent 决定"这条消息该走哪条路"；
- 工作流负责"把复杂任务拆成几步、按顺序走、关键处等用户确认"；
- 两者不冲突：顶层 Agent 遇到复杂任务时，自动"调用工作流模板"执行。

对用户：**"你只需要说，剩下的系统自己决定是随手答还是走流程。"**

## 六、边界与不做

- 不做全局 orchestrator 反思 / 重规划循环（冗余）
- 不重复实现工具，全部复用现有 `tools.py`
- 4 个专用 Agent 共用同一数据库会话，不新建连接
- 工作流保留独立入口，但产品上统一收口到「对话」心智

## 七、实施要点（已确认）

1. 前端对话界面沿用现状，后端 `/chat` 内部加顶层路由，不改前端。
2. 返回方式：对话展示结果 + 科研产物落盘 `output/research/` 并返回路径。
3. 4 个专用 Agent 统一由一个对话入口分发，不做独立入口。
