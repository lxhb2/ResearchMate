## 二、实现方案（架构与关键设计）

### 2.1 Q1-1 数据模型：零新表
复用 `Annotation` 模型现有字段（`backend/app/models/annotation.py`），语义约定：
- `content` = 原文 snippet（卡片标题）
- `comment` = 笔记正文（卡片主体，非空即视为「卡片笔记」）
- `position.rects` = 归一化矩形坐标（点击卡片跳回原文高亮）
- `position.color` = 色条颜色
- `position.cardOrder` = 拖拽排序号（float，组内排序）

后端路由 `backend/app/routers/annotations.py` 新增：
- `GET /annotations/pins`：按文献分组 + cardOrder 排序，附作者/年份/anchor
- `POST /annotations/reorder`：`{items:[{id}]}` 写 cardOrder
- `POST /annotations/{id}/send-to-writing`：`{project_id}` 追加 `- note（snippet，(Author, p. X)）` 到项目 content
- `_citation_anchor()`：生成 `(Author, Year, p. X)`，中英文作者通用（中文用全名/姓，多人加「等/et al.」）

前端：
- `ReaderPage.tsx`：划词工具条「📌 钉成卡片」→ `PinCardModal`；右侧 Tab（Chat | 卡片笔记）；`PinCardsPanel`（antd List + 拖拽）；点击卡片 `navigate(/reader/{paper_id}?page=X&flash=id)`，Reader 端读取 URL 参数做平滑滚动 + rects 高亮 + 脉冲闪烁（`index.css` 动画）
- `WritePage.tsx`：`openPinCards()` 拉取 pins → `insertPinCard()` 在光标处插入 `\n\n{note|snippet} {anchor}\n`，光标移动到插入内容末尾

### 2.2 Q1-2 综述生成管线
后端 `backend/app/routers/papers.py` 新增 `POST /papers/batch/literature-review`，SSE 三阶段：

```
Step1  _build_review_context():
        每篇 paper 拉取 chunks → ThreadPoolExecutor 并行 mini 摘要
        （LLM 摘要；失败/超时降级为 chunk 拼接 + 标题）
Step2  构造 prompt：每 chunk 用短别名 [c1]/[c2] 标注（含页码），
        要求每段 claim 后紧跟 \citation{c1, c3}（可多别名）
        system 提示含引用示例，禁止编造别名
Step3  流式输出 + 后处理：
        regex 提取 \citation{...} → 按 alias_map 还原真实 chunk_id →
        _review_render_marker 按 style 渲染 (Author, Year, p. X) 样式
        末尾发 citations 元事件（chunk_id/paper_id/title/page/snippet/citation/anchor）
```

关键设计：
- **短别名引用**：长 UUID chunk_id 模型抄写易错 → 换 `c1..cN`，后处理还原，citation_count 从 0 修复到稳定命中
- **并行 + 超时**：`wait(fs, timeout=...)`，50 篇不超时
- **离线降级**：`LLMAdapter._mock_literature_review()` 在无 LLM 配置时生成带 `\citation` 的演示综述，链路可用
- **样式渲染**：`_review_render_marker`（apa: `(程琍琍, p. 3)`；gb7714: `(程琍琍，第 3 页)`；bibtex: `\cite{key}`）
- **作者名/年份防御**：中文 2-4 字保留全名；空年份不出现双逗号（`程琍琍, n.d., p. 1`）

前端：
- `frontend/src/api/papers.ts`：`literatureReview()` SSE 解析（parseSSE 复用）
- `LibraryPage.tsx`：多选（复用批量标签的选中态）→ 批量工具栏「生成综述…」→ `LitReviewModal`
- `LitReviewModal.tsx`：题目/结构/引用样式 → 确认后 `navigate('/chat?mode=litreview&...')`
- `ChatPage.tsx`：preset session 流式接收 delta，结束时渲染 citation 芯片（复用 P1-3 的 MessageBubble 结构）
- `WritePage.tsx`：`LitReviewModal` + `insertReview()` 把正文插入草稿光标处，`message.success('已插入综述段落（引用 N 条）')`

cd /workspace/backend && ./.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 前端（开发模式，热更新）
cd /workspace/frontend && npm run dev   # http://localhost:5173

## 五、已知限制与后续优化

1. **演示数据较少**：当前库仅 1 篇 ready 文献（CPTU 浮选论文）。如需演示 N 篇综述，先上传/导入更多文献，或扩展 seed 脚本注入多篇示例。
2. **send-to-writing 需要写作项目**：Reader 页「发送到写作」需先存在 Project（试用时先在写作页新建）。
3. **LLM 依赖**：未配置 LLM 时走 mock 演示综述（内容占位）；配置后基于真实 chunk 生成。
4. **citation 样式细节**：GB/T 7714 与 BibTeX 的期刊级精确格式（如卷期页码）可后续在 `_review_render_marker` 中增强。
5. **卡片跨文献跳转**：当前跨文献跳转会新建 Reader 会话；如需无感返回原页面可加路由缓存。
6. **综述上下文预算**：`_REVIEW_CONTEXT_BUDGET` 截断超长上下文，超出的文献只在 mini 摘要层参与。
